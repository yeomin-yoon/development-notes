C++ 캐스팅 4종

2026년 7월 09일

Summary

C++ 캐스팅 4종은 “어떤 의도로 타입을 바꾸는지”를 코드에 드러내기 위해 나뉜 문법이다.

C 스타일 캐스팅 (Type)Value보다 C++ 캐스팅을 쓰는 이유는 변환 의도를 더 명확하게 남기기 위해서다.

왜 C 스타일 캐스팅을 피할까?

C 스타일 캐스팅은 짧다.

하지만 어떤 의도로 변환했는지 잘 드러나지 않는다.

C++ 캐스팅은 이 의도를 문법으로 나눈다.

코드가 조금 길어지지만, 위험한 변환을 검색하고 리뷰하기 쉬워진다.

1. static_cast

static_cast는 가장 일반적으로 쓰는 캐스팅이다.

컴파일러가 “이 변환은 문법적으로 가능한 관계다”라고 판단할 수 있을 때 사용한다.

static_cast: 숫자 타입 변환

결과:

소수점이 사라지는 것처럼 값 손실이 있을 수 있다.

static_cast는 이런 손실을 막아주는 것이 아니라, 개발자가 의도적으로 변환했다는 것을 표시한다.

static_cast: 업캐스팅

자식 객체를 부모 포인터로 보는 것은 안전한 변환이다.

이런 변환은 보통 암시적으로도 가능하다.

상속과 실제 객체 타입 기준 호출은 가상 함수와도 연결된다.

static_cast: 다운캐스팅

부모 포인터를 자식 포인터로 바꾸는 것도 static_cast 문법상 가능할 수 있다.

하지만 CharacterPtr가 실제로 Player 객체를 가리키는지는 검사하지 않는다.

실제 객체가 Player가 아니라면 이후 사용은 정의되지 않은 동작으로 이어질 수 있다.

Important

static_cast 다운캐스팅은 “내가 실제 타입을 확실히 알고 있다”는 전제가 있을 때만 사용한다. 확실하지 않다면 dynamic_cast나 엔진/프레임워크의 안전한 캐스팅 함수를 사용한다.

2. dynamic_cast

dynamic_cast는 상속 관계에서 실제 객체 타입을 런타임에 확인한다.

주로 부모 포인터나 부모 참조를 자식 타입으로 바꿀 때 사용한다.

실제 객체가 Player이면 성공한다.

실제 객체가 Player가 아니면 포인터 캐스팅은 nullptr을 반환한다.

참조로 dynamic_cast하면?

참조는 nullptr이 될 수 없다.

그래서 실패하면 예외를 던진다.

필요한 조건

dynamic_cast가 실제 타입을 확인하려면 기반 클래스가 **다형 타입(polymorphic type)**이어야 한다.

쉽게 말해 기반 클래스에 virtual 함수가 하나 이상 있어야 한다.

그리고 RTTI(Runtime Type Information)가 활성화되어 있어야 한다.

3. const_cast

const_cast는 const 또는 volatile 속성을 제거하거나 추가할 때 사용한다.

가장 흔한 상황은 오래된 C API가 char*를 요구하지만 실제로 내용을 수정하지 않는 경우다.

하지만 이 코드는 조심해야 한다.

const_cast는 타입에서 const 표시를 지울 뿐, 원래 객체가 수정 가능한지까지 바꿔주지 않는다.

반대로 원래 객체가 수정 가능한데, 중간에 const로 보였던 경우는 수정 가능하다.

4. reinterpret_cast

reinterpret_cast는 같은 주소나 비트를 전혀 다른 타입처럼 해석하겠다는 캐스팅이다.

포인터를 정수 주소값으로 바꾸거나, 저수준 시스템 코드에서 타입을 강제로 재해석할 때 사용한다.

하지만 일반 코드에서는 거의 피하는 편이 좋다.

왜 위험할까?

reinterpret_cast는 객체의 의미를 안전하게 변환하지 않는다.

이 코드는 double 객체가 있는 메모리를 int 객체가 있는 것처럼 보겠다는 뜻이다.

문제가 될 수 있는 이유:

즉 “값 변환”이 아니라 “메모리 해석 변경”이다.

Caution

바이트 해석이나 직렬화가 목적이라면 reinterpret_cast로 구조체 포인터를 바로 덮어씌우기보다 std::memcpy, 명시적 파싱, C++20 std::bit_cast 같은 방법을 먼저 고려한다.

포인터 캐스팅 비교

상속 구조가 있다고 하자.

static_cast

static_cast는 상속 관계만 보고 허용한다.

실제 객체가 Player인지 확인하지 않는다.

dynamic_cast

실제 객체가 Player가 아니므로 P는 nullptr이 된다.

Unreal에서는 Cast<T>()

Unreal의 UObject 계열에서는 보통 C++ dynamic_cast를 직접 사용하지 않는다.

대신 Unreal의 리플렉션 정보를 이용하는 Cast<T>()를 사용한다.

실패하면 nullptr을 반환한다.

Unreal 코드에서는 UObject 타입 확인에 IsA()나 Cast<T>()를 주로 사용한다.

이 차이는 Unreal의 Reflection 시스템을 이해하면 더 잘 보인다.

정리

  1. C++ 캐스팅 4종은 변환 의도를 명확히 나누기 위한 문법이다.
  2. static_cast는 일반 변환과 확신 있는 상속 변환에 사용한다.
  3. dynamic_cast는 실제 객체 타입을 런타임에 확인한다.
  4. dynamic_cast는 다형 타입과 RTTI가 필요하며 실패 시 포인터는 nullptr이 된다.
  5. const_cast는 const 표시를 제거할 수 있지만 원래 const 객체를 수정하면 안 된다.
  6. reinterpret_cast는 메모리 재해석이므로 일반 코드에서는 최대한 피한다.
  7. Unreal의 UObject 계열은 보통 dynamic_cast 대신 Cast<T>()를 사용한다.
