템플릿(Template)

Summary

템플릿은 타입이나 컴파일 타임 값을 매개변수로 받아, 여러 타입에 같은 코드를 재사용하게 하는 C++ 기능이다.

기능별 쓰임

필요한 것사용할 기능
타입만 다른 같은 코드함수·클래스 템플릿
컴파일 타임 값을 타입에 포함비타입 템플릿 매개변수
특정 타입만 다른 구현특수화 또는 오버로딩
타입에 따라 코드 분기if constexpr
받을 수 있는 타입 제한Concepts와 requires
개수가 다른 인자 처리가변 인자 템플릿
인자의 lvalue·rvalue 성질 유지Perfect Forwarding

왜 사용하는가?

타입만 다르고 동작이 같은 코드를 타입마다 작성하면 중복이 생긴다.

템플릿을 사용하면 하나로 표현할 수 있다.

컴파일러가 타입을 검사하므로 타입 안전성을 유지하면서 코드를 재사용할 수 있다.

인스턴스화

템플릿은 코드를 만들기 위한 틀이다. 컴파일러가 실제 타입이나 값을 넣어 함수·클래스를 만드는 과정을 **템플릿 인스턴스화(Template Instantiation)**라고 한다.

컴파일러 최적화에 따라 생성된 코드가 인라인되거나 합쳐질 수 있지만, 언어 개념상 타입별 코드가 인스턴스화된다고 이해하면 된다.

함수 템플릿

여러 타입에 같은 알고리즘을 적용한다.

클래스 템플릿

저장 타입만 다르고 구조와 동작이 같은 클래스를 만든다.

std::vector<T>, std::map<K, V>, TArray<T>, TMap<K, V>가 대표적인 클래스 템플릿이다.

비타입 템플릿 매개변수

타입이 아니라 컴파일 타임 값도 받을 수 있다.

Size가 배열 크기와 객체의 메모리 크기에 직접 영향을 준다.

표준 라이브러리의 std::array<int, 10>도 같은 방식이다. 실행 중 배열 크기가 결정된다면 std::vector나 TArray를 사용한다.

Note

여기까지가 템플릿의 기본이다. 여러 타입에 같은 코드가 필요하면 함수·클래스 템플릿을, 컴파일 타임 값이 필요하면 비타입 매개변수를 사용한다.

고급 기능

기능한 줄 역할
특수화특정 타입 패턴만 다른 구현 사용
if constexpr타입에 따라 컴파일할 코드 선택
Concepts템플릿이 받을 수 있는 타입 조건 선언
가변 인자 템플릿개수가 정해지지 않은 타입·값 처리

1. 특수화

특정 타입에서만 다른 구현을 사용한다.

Serializer<int>는 일반 구현을 사용하고 Serializer<FString>은 전용 구현을 사용한다.

  • 전체 특수화: 특정 타입 조합 전체를 별도 구현
  • 부분 특수화: 일부 타입 패턴만 별도 구현

함수 템플릿은 부분 특수화를 지원하지 않으므로 보통 함수 오버로딩을 사용한다.

2. if constexpr

if constexpr는 컴파일할 때 조건을 판단하여, 조건에 맞는 코드만 컴파일하는 if문이다.

구분일반 ifif constexpr
조건 판단실행할 때컴파일할 때
양쪽 분기모두 유효한 코드여야 함선택되지 않은 타입 의존 분기는 인스턴스화하지 않음
주된 용도값에 따른 실행 흐름타입에 따라 가능한 연산 구분

조건은 반드시 컴파일할 때 결과를 알 수 있어야 한다.

Note

흔히 선택되지 않은 코드는 “아예 컴파일하지 않는다”고 표현한다. 정확히는 기본적인 C++ 문법 검사는 하지만, 해당 타입에 의존하는 코드의 유효성 검사와 코드 생성은 하지 않는다.

3. Concepts와 requires

템플릿이 받을 수 있는 타입의 조건을 선언한다.

+ 연산을 지원하지 않는 타입은 요구 조건을 만족하지 않는다. C++20 Concepts를 사용하면 템플릿 의도가 분명해지고 오류 메시지도 이해하기 쉬워진다.

4. 가변 인자 템플릿

개수가 정해지지 않은 타입과 값을 받는다.

  • Args...: 타입 묶음인 매개변수 팩(Parameter Pack)
  • Values...: 전달된 값 묶음
  • (..., expression): 팩을 펼쳐 처리하는 Fold Expression

로그 함수, 이벤트·델리게이트, 객체 생성 함수처럼 인자 개수가 달라질 수 있는 기능에 사용한다.

5. Perfect Forwarding

받은 인자의 lvalue·rvalue 성질을 유지해서 다른 함수에 전달한다.

Args&&가 타입 추론과 함께 사용되면 Forwarding Reference가 될 수 있다. std::forward는 원래 인자의 값 범주를 보존해 불필요한 복사를 줄인다.

std::make_unique, std::make_shared, Emplace 계열 함수에서 자주 볼 수 있다.

더 깊은 심화 주제

처음부터 모두 구현할 필요는 없다. 코드를 읽다가 만났을 때 역할을 구분하면 된다.

주제역할
Type Traits타입의 성질을 컴파일 시점에 확인·변환
SFINAE잘못된 템플릿 후보를 오류 대신 후보에서 제외
CTAD생성자 인자로 클래스 템플릿 타입 추론
Deduction GuideCTAD의 타입 추론 규칙 지정
CRTP파생 타입을 템플릿 인자로 받아 정적 다형성 구현
템플릿 메타프로그래밍컴파일 시점에 타입·값 계산

C++20 이후 새 코드는 복잡한 SFINAE보다 Concepts와 requires를 우선 고려하는 편이 읽기 쉽다.

구현을 헤더에 두는 이유

다른 .cpp 파일에서 Box<int>를 인스턴스화하려면 그 파일을 컴파일하는 시점에 템플릿의 전체 구현을 볼 수 있어야 한다.

그래서 템플릿은 보통 헤더나 헤더에서 포함하는 .inl 파일에 구현한다.

사용할 타입을 미리 정할 수 있다면 구현을 .cpp에 두고 **명시적 인스턴스화(Explicit Instantiation)**할 수도 있다.

이 경우 미리 준비한 타입을 중심으로 사용할 수 있도록 선언과 링크 구성을 맞춰야 한다.

비용과 주의점

컴파일 시간

복잡한 템플릿을 많은 타입으로 인스턴스화하면 컴파일 시간이 늘어날 수 있다.

코드 블로트

타입별 코드가 생성되어 실행 파일 크기가 증가할 수 있다. 컴파일러와 링커가 동일한 코드를 합치거나 인라인할 수도 있으므로 항상 크게 증가하는 것은 아니다.

오류 메시지

템플릿 오류는 실제 타입으로 인스턴스화할 때 나타난다. 중첩 템플릿이 많으면 오류 메시지가 길어질 수 있으며 Concepts가 이를 개선하는 데 도움을 준다.

Note

템플릿이라고 실행 비용이 무조건 없는 것은 아니다. 가상 함수와 같은 동적 디스패치가 기본적으로 필요하지 않을 뿐, 생성된 코드가 수행하는 연산 비용은 그대로 존재한다.

언제 템플릿을 사용하지 않을까?

필요한 것적합한 도구
실행 중 실제 객체에 따라 행동 변경가상 함수
플랫폼·빌드 설정에 따라 코드 포함·제외전처리 매크로
여러 타입에 같은 코드 적용템플릿

가상 함수와 매크로는 템플릿의 대체품이 아니라 서로 다른 문제를 해결하는 도구다.

학습 우선순위

최종 정리

  • 템플릿: 타입이나 컴파일 타임 값을 받는 코드의 틀
  • 인스턴스화: 실제 타입·값을 넣어 함수나 클래스를 만드는 과정
  • 기본: 함수 템플릿, 클래스 템플릿, 비타입 매개변수
  • 실무 고급: 특수화, if constexpr, Concepts, 가변 인자, Perfect Forwarding
  • 구현은 보통 헤더에 두며 명시적 인스턴스화는 예외
  • 과도한 사용은 컴파일 시간과 코드 크기를 증가시킬 수 있음
